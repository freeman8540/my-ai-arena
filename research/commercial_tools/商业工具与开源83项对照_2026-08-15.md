## 1. 为什么必须分层

| | GitHub 开源 83 项 | 商业工具 138 项 |
|---|---|---|
| 收录对象 | 公开仓库、开放权重或可自建工作台 | 闭源 SaaS、商业桌面软件、云 API、订阅服务 |
| 维护位置 | `research/GitHub_AI_*_2026-08-13.*` | `research/commercial_tools/` |
| 数量口径 | **固定 83** | **固定 138**（本快照） |
| 典型价值 | 可审计、可自托管、可改流程 | 低门槛、托管算力、工业格式、数字人/TTS 产品化 |
| 不能互相替代的原因 | 多数仍要自备模型 API 或 GPU | 数据出境、套餐商用权、地区限制、无法审计源码 |

两边会出现“看起来都叫视频生成/小说工具”的名字，但 **Kling ≠ Wan2.2，剪映 ≠ ArcReel，蛙蛙写作 ≠ InkOS**。对照的目的是接线，不是合并清单。

## 2. 按工作流对照

### 2.1 中文长篇小说

| 你想要的结果 | 商业目录入口 | 开源 83 项入口 | 不要混用的点 |
|---|---|---|---|
| 今天就写，不想部署 | 蛙蛙写作、Dreamily、Kimi、DeepSeek、豆包 | `Nigh/show-me-the-story` | 商业侧省运维；开源侧正典/伏笔更透明 |
| 超长连载、状态机、审稿 | 没有完全对等的单一 SaaS | `webnovel-writer`、`ainovel-cli`、`oh-story-claudecode` | 不要指望 ChatGPT 项目知识库等于 200 万字状态 |
| 综合 Agent / 小说 IDE | 蛙蛙写作、Novelcrafter | InkOS、Denova、OpenFic、Goink、Siming | 商业产品很少同时覆盖翻译+互动影游+开放世界 |
| 本地数据、可审计 | 基本不适用 | `novel-studio`、NeuroBook、StoryForge | 商业云端写作默认把正文交给供应商 |

### 2.2 剧本与分镜

| 你想要的结果 | 商业目录入口 | 开源 83 项入口 | 不要混用的点 |
|---|---|---|---|
| 工业格式剧本 | Final Draft、Arc Studio、WriterDuet、Fade In、Highland 2 | `lwhela12/AI-Screenwriting-Tool`、`ruvnet/aiscreenplay` | 开源侧社区和格式完整度明显弱于商业编剧软件 |
| 中文短剧编剧流程 | 蛙蛙写作、FinalBit | `short-drama`、`shanyin-screenwriting-master` | 开源多为 Skill，不是独立 SaaS |
| 小说转结构化剧本 | FinalBit、LTX Studio | `novel2script`、`openfrees/toonflow` | toonflow 仓库许可不是标准开源商用许可 |
| 剧本转镜头 Prompt / 分镜 | LTX Studio、Boords、StoryboardHero、Katalist | `neopen/story-shot-agent`（PenShot） | 商业分镜工具出图；PenShot 出可接模型的结构 |

### 2.3 短剧 / 漫剧生产

| 你想要的结果 | 商业目录入口 | 开源 83 项入口 | 不要混用的点 |
|---|---|---|---|
| 托管式小说视觉化 | LTX Studio + Kling/Sora/Runway + 剪映 | Toonflow-app、ArcReel、AIComicBuilder、LumenX | 开源工作台仍要外接商业视频 API |
| 资产、审核、费用、剪映草稿 | 剪映本身只做后期 | ArcReel | 不要把剪映当成开源制片系统 |
| 阿里云模型闭环 | 通义千问 + 商业视频 API | LumenX | LumenX 是开源工作台，模型仍是云服务 |
| 团队资产和异步任务 | StudioBinder / Celtx（前期） | Jellyfish | 商业侧强在通告制片，开源侧强在生成任务队列 |

### 2.4 镜头模型

| 你想要的结果 | 商业目录入口 | 开源 83 项入口 | 不要混用的点 |
|---|---|---|---|
| 不买 GPU，要高质量短镜头 | Sora、Runway、Kling、Hailuo、Vidu、Google Flow、Luma、Pika | 无对等托管项 | 开源模型仓库不是这些 SaaS 的源码镜像 |
| 消费级 GPU 本地出镜头 | 不适用 | Wan2.2 TI2V-5B、MAGI-1 4.5B、CogVideoX | 本地模型要自己扛显存和许可证 |
| 原生音画同步 | 商业侧看 Runway/Sora 等当前能力 | LTX-2 | LTX-2 有社区许可和收入门槛 |
| 训练/研究完整栈 | 通常不开放 | Open-Sora、SkyReels-V2 | 研究仓库不能当 Sora 替代品宣传 |

### 2.5 解说、口播、后期

| 你想要的结果 | 商业目录入口 | 开源 83 项入口 | 不要混用的点 |
|---|---|---|---|
| 主题到解说成片 | InVideo、Pictory、Fliki、剪映 | MoneyPrinterTurbo | 都是库存素材路线，不是剧情角色视频 |
| 转录改稿式剪辑 | Descript、OpusClip、VEED、Kapwing | 83 项中无完整对等 | 这类能力目前几乎只在商业侧成熟 |
| 数字人口播 | HeyGen、Synthesia、D-ID、Virbo | 工作台通过 API 调用 | 开源仓库有形象库的很少 |
| 配音 | ElevenLabs、讯飞智作、Fish Audio、云厂商 TTS | 工作台外接 TTS | 语音许可独立于 AGPL/MIT 工作台许可 |
| 专业时间线导出 | 剪映、Filmora、Adobe | Openframe（FCPXML/EDL）、ArcReel（剪映草稿） | 开源价值在“交得进后期软件” |

## 3. 推荐接线，而不是合并名单

### 接线 1：开源写小说，商业出镜头

```text
InkOS / show-me-the-story / webnovel-writer
  → PenShot 或人工分镜
  → Kling / Hailuo / Runway / Sora
  → 剪映
```

### 接线 2：商业写剧本，开源做资产流水线

```text
Final Draft / Arc Studio
  → Toonflow-app 或 ArcReel
  → 商业图像/视频 API
  → 剪映草稿或 FCPXML
```

### 接线 3：两边都不要 GPU

```text
ChatGPT / Claude / 蛙蛙写作
  → InVideo / 剪映 / HeyGen
```

或开源：

```text
MoneyPrinterTurbo + 云 LLM + 云 TTS
```

### 接线 4：数据不能出境

```text
不要用本商业目录的网页写作产品存未发表稿
  → 开源 novel-studio / StoryForge / Scriverse / 本地 Ollama
  → 本地 Wan2.2 / MAGI-1（若有 GPU）
```
